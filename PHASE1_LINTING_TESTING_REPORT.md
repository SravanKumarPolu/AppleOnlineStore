# NovaCart — Phase 1: Linting, Type Safety & Test Execution Report

**Scope:** Linting/testing portion of Phase 1 only. Security and reliability
gates are separate and NOT claimed complete by this report.

**Environment used for validation:** Node v24.21.0, npm (ci installs), no
MongoDB instance, no SMTP server. All results below come from actual command
executions; exit codes are recorded per command.

## 1. Root causes per error category

| Category | Root cause |
|---|---|
| Frontend: generated `dev-dist/workbox-*.js` linted (10 errors + 4 warnings) | `eslint.config.js` only ignored `dist`, not the PWA dev output `dev-dist/` (generated by `vite-plugin-pwa` `devOptions.enabled`). The file contained stale `eslint-disable` directives for rules that do not exist in the installed plugin versions. |
| Frontend: 11 `react-hooks/rules-of-hooks` errors | `BestSeller.tsx`, `LatestCollection.tsx`, `pages/Product.tsx` called `useState`/`useEffect` **after** conditional early returns (`if (!context) return`, `if (!products) return`). Hook count varied between renders — a latent crash ("Rendered more hooks…") whenever products loaded after mount. |
| Frontend/Admin: `no-explicit-any` (33 + 8) | PayPal SDK callbacks, WebSocket payloads, cart amount helpers, address state, analytics state, axios error handlers and generic API envelopes were all typed `any`. |
| Frontend/Admin: `exhaustive-deps` warnings (9 + 7) | Fetch/effect functions were plain functions or non-`useCallback` dependencies (context/hook objects whose identity changes every render), so authors either omitted them or listed whole objects that would have caused render loops. |
| Admin: Fast Refresh warning in `App.tsx` | `App.tsx` exported non-component constants (`backendUrl`, `currency`) alongside the component. |
| Backend: ESLint 8.57.1 exit 2 | **No ESLint configuration file existed at all** (`eslint .` searched ancestors and found nothing). |
| Backend: `npm test` crashed (`ERR_MODULE_NOT_FOUND bcryptjs`) | `scripts/test-utilities.js` imported `bcryptjs`, which is not a dependency (the backend uses native `bcrypt`); the file also mixed ESM `import` with CJS `module.exports` under `"type": "module"`, and `run-tests.js` used `require.main === module`. Additionally it imported non-existent model paths (`models/User.js` etc. instead of `userModel.js`/`analyticsModel.js`). |
| Backend lint findings after config added (16 errors) | Two **real runtime bugs**: (a) `emailService.js` order-confirmation template used `${{totalAmount}}`, which JS parses as template interpolation of an undefined variable → `ReferenceError` when the email is built; (b) `test-utilities.js` used `queryStartTime` before it was ever declared. Plus dead imports/vars, four pass-through `try { … } catch (e) { throw e; }` wrappers, and a dead `getCountryCode` helper. |
| Backend test data bug | `createMultipleTestUsers` generated names like `Test User 1`, but the User model validator only allows letters/spaces in names → `ValidationError` before the DB was even reached. |

## 3. Potentially behavior-affecting changes

All are deliberate and guarded by tests; none change business rules:

1. **BestSeller / LatestCollection / Product hook reordering** — hooks now run
   before early returns. This *fixes* a latent crash when products load after
   mount; rendering output for the already-working paths is identical.
   Verified by the "recovers when products load after mount" test, which fails
   on the pre-fix code.
2. **PWAInstallGuide device detection** — `setIsDesktop(!isIOS && !isAndroid)`
   previously read stale state, so `isDesktop` was **always true** (iOS/Android
   users saw desktop install instructions). Detection now uses local values:
   each platform sees its own instructions.
3. **PWARegistration install button** — the toast's Install button previously
   captured the first-render handler whose `deferredPrompt` was `null` (silent
   no-op). It now reaches the current handler via a ref, so clicking Install
   actually prompts.
4. **Collection sorting persistence** — when filters change while a sort is
   active, the sort is now re-applied (previously silently dropped, leaving the
   dropdown showing "Low to High" on an unsorted list). Implemented via
   functional `setState` so no effect loop is possible.
5. **Frontend Orders page** — uses `useNavigate()` directly instead of the
   context wrapper so the fetch effect is not re-triggered by provider
   re-renders (prevents redundant order API calls). Same navigation behavior.
6. **useCart.getCartAmount** — cart entries whose product no longer exists in
   the catalog are skipped via a guard instead of throwing into the existing
   `try/catch`. The computed total is unchanged.
7. **PayPal createOrder** — returns `data.orderId` only when present
   (`success && orderId` guard) instead of possibly `undefined`; the PayPal
   SDK requires a string. Failure paths throw the same errors as before.
8. **Backend email template** — `${{totalAmount}}` is now escaped
   (`\${{totalAmount}}`) so it renders as the literal `{{totalAmount}}`
   placeholder and is replaced by `replaceTemplateVariables` — previously this
   line threw `ReferenceError: totalAmount is not defined` when building the
   order-confirmation email.
9. **Backend test utilities** — `bcryptjs` → `bcrypt` (same API), CJS → ESM,
   correct model import paths, `queryStartTime` declared before use, and
   letter-only test-user names to satisfy the User model validator. The suite
   now executes real assertions instead of crashing at import time.
10. **Backend dead code removal** — unused imports (`SalesAnalytics`,
    `mongoose`, `crypto`), dead `getCountryCode` helper, dead `selectedUser`
    state (admin), and four pass-through try/catch wrappers removed. No
    reachable behavior changes.
11. **Fast Refresh splits** — `ShopContext` object + `useShopContext` moved to
    `frontend/src/context/shop-context.ts`; `backendUrl`/`currency` moved to
    `admin/src/config.ts`. Import-only refactors.

## 7. Follow-up session: unblocking the backend suite (ephemeral infra)

The suite was unblocked without any real services or credentials:

- `scripts/run_backend_tests_with_infra.mjs` (outside the repo, in the
  workspace `scripts/` dir) starts:
  1. `mongodb-memory-server` on `127.0.0.1:27017` (binary 7.0.14 — Debian 13
     hosts cannot fetch 6.x), and
  2. a minimal ESMTP stub on an unprivileged port (587 is EACCES for
     non-root; `SMTP_PORT` is injected) implementing EHLO/AUTH PLAIN/LOGIN/
     MAIL/RCPT/DATA/NOOP/QUIT. Nothing is delivered; no real credentials.
- It then spawns `npm test` with the missing env vars (`SMTP_*`, `APP_NAME`,
  `CORS_ORIGIN`, `TEST_MONGODB_URI`, `BCRYPT_ROUNDS=4`) and reports the real
  exit code, then tears everything down.

Five real bugs were found and fixed to reach 7/7:

1. `scripts/test-utilities.js` — product fixture no longer matched
   `models/productModel.js` (used `images` instead of `image`, lacked required
   `subCategory`, invalid `color`, wrong `stock`/`isActive` fields) → every
   product insert failed validation, breaking database/analytics/performance/
   integration categories.
2. `scripts/test-utilities.js` — fixed emails (`test@example.com`,
   `testuserN@example.com`, `admin@example.com`) collided with the unique
   email index when helpers ran more than once per run → unique per call/batch
   (uses the existing `generateRandomEmail()` helper).
3. `scripts/test-utilities.js` — order fixture drifted from
   `models/orderModel.js` (`shippingAddress`→`address` with 8 required fields,
   `paymentMethod: 'paypal'`→`'PayPal'` enum, `status`→`orderStatus`, required
   `subtotal/shipping/total`, items need `image`+`color`).
4. `services/emailService.js` — only 1 of 6 referenced templates shipped on
   disk (`templates/email/passwordReset.html`), and fallbacks were only used
   when the directory was entirely missing → `welcome`, `orderConfirmation`,
   `orderStatusUpdate`, `lowStockAlert`, `securityAlert` emails all threw
   "Template not found" at runtime (real production bug: checkout
   confirmation email broken). Fix: after loading disk templates, missing keys
   are filled from built-in fallbacks (disk files still win); three fallback
   templates that never existed were added.
5. `scripts/run-tests.js` — `isTestPassed()` did not recognize the
   integration result (a flat map of booleans), so an all-passing integration
   run was reported FAIL. Now a flat all-boolean object passes only when every
   entry is true.

Verification after these fixes: backend `npm run lint` still 0/0; full suite
7/7 PASS with exit 0 (see `backend_test_with_infra4.log`).

## 8. Unresolved risks

1. **Backend integration suite needs live services for a plain `npm test`** —
   resolved in practice by the ephemeral infra runner (§7) which achieves
   7/7 PASS; teams wanting a plain run still need real MongoDB + SMTP + env
   vars. `mongodb-memory-server` is already a devDependency.
2. **Committed secrets** — `backend/.env` contains real PayPal, Cloudinary,
   JWT and admin credentials and is inside the repo/ZIP. This is a security
   risk that belongs to the separate Phase 1 security gate (flagged, not fixed
   here — out of scope for the linting/testing milestone).
3. **Admin has zero automated tests** — adding a runner would introduce new
   devDependencies; deferred as a decision for the team.
4. **`backend/services/analyticsService.js` is dead code in CJS format** under
   an ESM package (imports it nowhere). Lint-clean now, but it would crash if
   ever imported as-is. Candidate for deletion or ESM conversion later.
5. **Missing backend scripts** referenced by `package.json`: `db:seed`
   (`scripts/seed-database.js`), `db:migrate` (`scripts/migrate-database.js`),
   `email:test` (`scripts/test-email.js`) do not exist. Reported as pending
   work; not implemented in this milestone.
6. **Env-var parity** — `CORS_ORIGIN`, `SMTP_*`, `APP_NAME` are expected by the
   test runner but absent from the committed `.env`; deployment config must
   supply them.
7. **WebSocket `connect` stability** — `useWebSocket`'s `connect` callback
   depends on non-memoized handler props from the provider (pre-existing
   architecture, untouched to avoid behavior change). No lint warning fires,
   but socket re-subscription frequency is a known design smell for a future
   hardening pass.
8. **Backend `npm run build` is a placeholder** — no compile/type step exists
   for the backend; JS regressions there are only caught by lint + runtime
   tests.
